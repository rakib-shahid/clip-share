# Slice 0.17: Self-service password change

## Status

**Completed 2026-09-06.** The authenticated, compare-and-swap protected API and
account-menu password flow are implemented; existing sessions remain valid.

## Accepted contract

- Active users, including the super-admin, can change only their own password.
- `POST /api/me/password` accepts `currentPassword`, `newPassword`, and
  `confirmPassword`; it is authenticated and CSRF protected.
- The current password is verified; existing 8–128 character rules and matching
  confirmation are enforced; the Argon2id hash is replaced atomically.
- A forgotten password still requires an administrator reset.
- Password values never enter URLs, logs, API responses, or client persistence.
- Existing signed sessions remain valid until their normal 24-hour expiry.

## Decisions required

1. **Confirmed:** a compact account menu contains **Change password** and
   **Log out** for every active user.
2. **Confirmed:** reject a new password identical to the current password with
   `new_password_unchanged`.
3. **Confirmed:** update with compare-and-swap on the verified hash; if another
   reset/change wins, return the safe `current_password_incorrect` result rather
   than overwriting it.
4. **Confirmed:** return `204 No Content` on success; clear modal fields before
   closing; use `current-password` for the current field and `new-password` for
   both new fields.

## Verification

- Store, HTTP, component, and browser tests cover success, authorization, CSRF,
  incorrect current password, validation, concurrent reset/change, and retained
  sessions.
