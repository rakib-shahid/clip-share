# Slice 2.21: Typed explorer item model

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2. Depends on 2.16.** Introduced one pure discriminated
view model so grid/list and menus cannot interpret API states differently.

## Work

- Map `Folder` to `{kind:"folder"}` and `ClipSummary` to `{kind:"clip"}` without
  losing numeric IDs, owner, counts, state, progress, size, date, job, or public ID.
- Derive display status, preview eligibility, progress kind, secondary metadata,
  stable React key prefixed by kind, and accepted action capability flags.
- Treat unknown clip states as non-previewable with visible `Unknown status` and
  no destructive job action; do not coerce them to ready.
- Keep formatting and event handlers outside the model.

## Verification

Pure unit tests cover every known/unknown state, null job/progress/size, duplicate
numeric folder/clip IDs, normal/admin capabilities, and immutable input objects.

## Implementation evidence

- The pure `ExplorerItem` union retains source identity, ownership/counts, clip
  state/job/progress/size/date/error/public ID, and prefixes stable keys by kind.
- One mapping owns display status, preview eligibility, progress kind, secondary
  metadata, and role/state-aware capabilities. Unknown states are visible,
  non-previewable, and receive no destructive capability.
- Twelve focused cases cover all schema states, an unknown future state, nulls,
  duplicate numeric IDs, roles, roots, job presence, and input immutability.
