# Slice 2.17: Explorer preference storage

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2. Depends on 2.14.** Added a small typed local
preference module with no UI consumer.

## Work

- Store version-1 JSON under `clip-share.preferences.v1.<actingUserId>`.
- Validate and expose explorer `{view, sort}`, search `{view}`, and trash
  `{view}` independently. Defaults are explorer grid/latest, search grid, and
  trash grid.
- A preference follows the signed-in actor across administered libraries.
- Catch unavailable/denied/quota/parse/write errors and use in-memory defaults.
- Subscribe to valid same-origin `storage` events; ignore wrong keys, actors,
  versions, shapes, or enum values. Never persist names, paths, or session data.
- Expose changed fields to consumers: a cross-tab sort change must start a
  coordinated page-one reload, while a view-only change relayouts current items
  without fetching. Do not write back while applying an external event.

## Verification

Unit tests cover defaults, round trip, actor isolation, partial/malformed/legacy
JSON, thrown storage methods, write failure, cross-tab update, listener cleanup,
no event echo, sort-versus-view effects, and prototype-pollution-shaped input.

## Implementation evidence

- `explorer-preferences.ts` stores only versioned view/sort enums under the
  acting user's key, validates each preference independently, and safely falls
  back to in-memory state when browser persistence is unavailable.
- Subscribers receive exact changed fields; valid storage events update state
  without write-back, while wrong actors, versions, and shapes are ignored.
- Focused tests, ESLint, TypeScript, and the production build pass.
