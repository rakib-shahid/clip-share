# Slice 2.3: Editor Dialog migration and title-focus regression

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2. Depends on 2.2.** The
editor shell and nested editor surfaces use Dialog, and title focus theft is
eliminated.

## Work

- Replace the relevant `Modal` compositions in `editor-dialog.tsx` with Dialog.
- Initial focus enters the intended player/control for the shell and the title
  Input for details; it runs once per open.
- Title `onChange` updates local draft only. Enter/Save sends one metadata PATCH;
  Escape/Cancel sends none. Preserve selection/caret and typed text through
  parent rerenders and request-state changes.
- Keep the heartbeat request unchanged; it does not drive UI state or focus.
- While saving, prevent outside/Escape close without disabling the focused Input
  in a way that loses caret unnecessarily.

## Verification

Use a controlled test that types an entire title and forces callback-identity,
heartbeat, and saving-state rerenders after characters. Assert uninterrupted
focus/value, exactly one request on submit, none per keystroke, and correct focus
return. Preserve editor playback, Space-key, nested inertness, and discard tests.

## Implementation evidence

- Preparing, editor, unpreviewed-finalize, discard, and Edit clip details
  surfaces now compose the shared Radix-backed Dialog parts; no `Modal` import
  remains in `editor-dialog.tsx`.
- Initial editor readiness focuses Edit details once. The nested title Input is
  explicitly focused/selected once per open and returns focus to that trigger.
  Controlled busy state blocks Escape/outside dismissal without disabling the
  Input.
- Title editing is local until form submit. Enter/Save sends one trimmed metadata
  PATCH, while Escape/Cancel sends none. The heartbeat remains a state-free POST.
- The initial editor fetch no longer repeats when a parent supplies a new
  `onClose` callback identity; an internal callback ref preserves the latest
  handler without destabilizing the request effect.
- Three editor regression tests cover character-by-character callback rerenders,
  heartbeat, pending save, nested inertness/focus return, cancellation, Space-key
  playback, and discard. Frontend lint, all 21 tests, production build, and the
  rebuilt Compose runtime passed on September 12, 2026.
