# Slice 2.12: Status and feedback primitives

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2. Depends on 2.1.** The
upstream display primitives required by later consumers are installed without
changing feature layouts.

## Work

Add Radix-backed shadcn `Badge`, `Empty`, `Skeleton`, `Spinner`, `Progress`,
`Tooltip`, and `Sonner` through the pinned workflow. Mount one themed Toaster at
the application root. Preserve upstream APIs; theme via tokens. Progress accepts
measured values only. Tooltip content supplements visible/accessible labels.

## Verification

Primitive tests cover accessible status text, progress min/max/value, no
percentage on Spinner, tooltip keyboard/pointer access, toast live-region
behavior/dismissal, dark-theme contrast, and reduced-motion CSS. No feature uses
the primitives until its own slice.

## Implementation evidence

- Badge, Empty, Skeleton, Spinner, Progress, Tooltip, and Sonner sources are
  installed and recorded in the registry manifest; direct dependencies are
  pinned exactly.
- One forced-dark themed Toaster and one Tooltip provider are mounted at the
  application root. Progress requires a measured numeric value and preserves
  Radix min/max/value semantics.
- Focused tests cover visible/status text, measured Progress ARIA, Spinner
  semantics, Empty/Skeleton output, keyboard Tooltip access, and toast dismissal.
