# Slice 2.7: Explorer destructive Alert Dialogs

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2. Depends on 2.6.** Explorer
deletion, processing cancellation, and failure dismissal confirmations use the
shared Alert Dialog.

## Work

- Ready clip trash: consequence text, Cancel, and Move to recycle bin; no checkbox.
- Folder trash: retain recursive summary loading/retry, totals, acknowledgement
  checkbox, and disabled action until acknowledged.
- Processing cancellation and failed-upload dismissal retain their distinct
  irreversible wording and API routes; neither gains a checkbox.
- During requests, keep the surface open, disable duplicate actions, reject all
  close paths, and show safe inline errors.

## Verification

Component/API-mock tests cover every action/cancel path, summary failure/retry,
acknowledgement reset per open, busy dismissal attempts, exactly-once mutations,
and focus return to the originating item's action trigger.

## Implementation evidence

- Ready clip trash, folder trash, job cancellation, and failure dismissal retain
  their distinct routes, wording, retry, acknowledgement, and inline errors.
- Async actions prevent Alert Dialog auto-close and lock dismissal while busy.
- Focused API-mock tests cover clip deletion, both job routes, duplicate
  activation, recursive totals, acknowledgement gating, and successful refresh.
