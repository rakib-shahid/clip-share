# Slice 2.27: Navigation and request coordination

## Status and outcome

**Completed September 13, 2026. Parent: main spec 2. Depends on 2.13, 2.16, 2.25, and 2.26.** Folder,
history, sort, refresh, and processing-poll requests commit atomically.

## Work

- Centralize folder-page loading with both an AbortController and a monotonic
  generation ID. Abort superseded work for efficiency; independently require a
  matching generation, folder, and sort before any response may update page,
  cursor, URL, focus target, busy state, or error. Aborted requests show no error.
- Keep the committed collection visible and inert during navigation/sort, with
  Spinner/status. Commit data and push/replace history only after success.
- On failed popstate navigation, restore the last committed URL/state with
  `replaceState`. Normal failed navigation never creates a history entry.
- Poll slice 2.26's endpoint every two seconds only while the loaded collection
  contains active jobs,
  sending one request per chunk of at most 100 IDs and stopping on unmount or
  when none remain. Merge successful statuses into matching loaded items without
  replacing pages. Retry transient poll failure on the next interval without
  clearing data. An omitted requested job triggers one coordinated page-one
  reconciliation for that missing-ID set.
- Latest/oldest/name sorts merge terminal updates in place. A terminal update or
  changed size/state key under size/state sorting starts a coordinated page-one
  reload. No poll may overwrite newer navigation, reorder locally against the
  server, or replay entry motion.

## Verification

Deferred-promise tests cover out-of-order responses, abort, rapid ancestors,
rapid sorts, popstate failure, refresh during navigation, poll races, unmount,
URL/state commits, retained content, inertness, and status announcements. Client
tests cover chunking, stop/retry, missing-job reconciliation, and stable-sort
merge versus key-changing reset; slice 2.26 owns endpoint validation and
authorization tests.
