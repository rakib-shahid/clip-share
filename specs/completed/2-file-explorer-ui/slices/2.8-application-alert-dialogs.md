# Slice 2.8: Application-wide destructive Alert Dialogs

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2. Depends on 2.3, 2.5, and
2.6.** Destructive application confirmations no longer use the custom Modal.

## Work

- Migrate editor discard and finalize-without-current-preview warnings, permanent
  trash purge, user disable/archive/delete-library actions, and upload discard.
- Preserve each existing acknowledgement rule, three-action editor warning,
  nested modal order, authorization, request, retry, and busy-lock behavior.
- Use ordinary Dialog rather than Alert Dialog only where a warning offers a
  non-terminal workflow such as starting preview; document that exception in
  the consumer test.

## Verification

Feature tests assert wording/actions, checkbox gates, topmost focus, no background
interaction, exact mutation counts, errors, and busy close prevention. `rg` finds
no destructive confirmation still implemented with `Modal`.

## Implementation evidence

- Editor discard, permanent Trash purge, user disable/archive/library deletion,
  and both upload-cancellation paths use Alert Dialog with busy close guards.
- User edit/password/enable/restore remain ordinary Dialog workflows.
- The editor's preview-first three-action warning remains an ordinary Dialog as
  the documented non-terminal exception.
- Existing editor, user-management, dialog, and API-mock suites pass with the
  application-wide migrations.
