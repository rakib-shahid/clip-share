# Slice 2.33: Viewport file-drop upload

## Status and outcome

**Completed September 13, 2026. Parent: main spec 2. Depends on slices 2.27 and
2.29.** A video file dragged anywhere over the active explorer now enters the
existing clip-upload flow and defaults to the currently committed folder.

## Work

- Listen at the explorer viewport boundary for native file drag events. Ignore
  text, links, and other non-file drags, and prevent the browser from navigating
  away when a file is dropped.
- While a file is over the viewport, show a non-interactive full-screen overlay
  with a dashed target, upload icon, current destination, and reduced-motion-safe
  fade. Nested drag-enter/leave events must not flicker the overlay.
- On drop, select the first file and open the existing upload Dialog. Prepopulate
  its filename-derived title, required compression state, and current folder,
  while retaining destination changes, validation, progress, cancel, and editor
  handoff behavior from slice 2.29.
- Keep the existing Dialog-local picker and replacement drop target operational.
  While the upload Dialog is already open and idle, its entire viewport remains
  a drop target and a drop outside the small Attachment area selects or replaces
  the pending file. Disable replacement during transfer, nested destination
  picking, and cancellation confirmation.

## Verification

- Component tests prove non-file drags are ignored, file drags display the
  destination overlay, drag-over requests copy semantics, and a viewport drop
  opens the upload Dialog with the file, derived title, and current folder.
- Dialog tests and a browser test prove a viewport drop also selects and replaces
  the file while the upload Dialog is already open.
- Lint, React tests/build, browser smoke coverage, and Docker runtime checks pass.
