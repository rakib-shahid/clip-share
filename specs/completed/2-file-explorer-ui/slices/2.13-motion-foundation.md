# Slice 2.13: Motion foundation

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2. Depends on 2.1.** A small,
accessible animation foundation is installed without animating explorer items.

## Work

- Pin `motion` to `13.1.1`; wrap the application in
  `MotionConfig reducedMotion="user"` and import from `motion/react`.
- Export shared 160–240 ms transition values and restrained fade/slide variants.
- Prefer `LazyMotion`/the smallest feature bundle that supports accepted layout
  animation; do not add Motion+ or paid-only APIs.
- Keep the existing CSS reduced-motion fallback for non-Motion transitions.
- Leave Dialog, Alert Dialog, Drawer, Dropdown Menu, Context Menu, Tooltip, and
  Sonner portal transitions to their shadcn/Radix/Vaul CSS. Motion is limited to
  explorer collection/layout/navigation and item feedback.

## Verification

Tests cover root configuration, normal variants, reduced-motion opacity-only
variants, no input delay, and absence of perpetual decorative motion. Record the
production bundle delta for comparison after custom code removal.

## Implementation evidence

- `motion` `13.1.1` is pinned and the root uses `MotionConfig
  reducedMotion="user"` with strict `LazyMotion` and `domAnimation`.
- Shared 160ms, 200ms, and 240ms transitions and fade/slide variants are
  exported; reduced variants remove all spatial movement and none repeat.
- Focused tests cover provider rendering, immediate input, timing bounds, and
  reduced variants. The production bundle delta is +69.35kB minified / +24.21kB
  gzip versus the slice 2.12 build.
