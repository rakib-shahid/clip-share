# Slice 2.30: Search result convergence

## Status and outcome

**Completed September 13, 2026. Parent: main spec 2. Depends on 2.5, 2.12, 2.17, and 2.21.** Reuses Item
presentation and view preferences in Search without changing search ranking.

## Work

- Preserve query validation, 100-result cap, API relevance/path order, owner
  context, recycle-bin exclusion, and navigate/show-in-folder behavior.
- Replace initial/loading/no-results/results markup with Field/Input, Skeleton,
  Empty, Badge, Item/ItemGroup, and matching grid/list Toggle Group.
- Store search view independently. Do not expose explorer sort controls because
  client sorting would misrepresent server result order.
- A result's primary action opens a folder or shows a clip in its folder as now;
  only actions supported by SearchResult data are rendered.

## Verification

Tests cover blank/query/error/loading/empty/100-cap states, grid/list persistence,
stable API order, normal/admin owner labels, folder/clip navigation once,
keyboard access, 320 px layout, and no explorer sort leakage.
