# Slice 2.28: Collection motion, states, and Load more

## Status and outcome

**Completed September 13, 2026. Parent: main spec 2. Depends on 2.12, 2.13, and 2.27.** Finished explorer
collection transitions and replace custom loading/empty/pagination markup.

## Work

- Initial load uses view-shaped Skeletons; empty uses shadcn Empty with Create
  folder and visible guidance to Upload clip; page errors use accessible Alert-
  styled content and Retry.
- Animate committed collection replacement in navigation direction. Initial
  entry staggers at most eight items by ~15 ms. Grid/list and sort use coordinated
  layout motion without stagger; polling never triggers entry motion.
- Load more sends current sort+cursor, preserves existing items/focus, disables
  duplicate activation, and appends only a matching latest response. Show append
  errors and Retry beside the action without replacing the page.
- Deduplicate defensively by kind+ID while treating a duplicate as a test/logging
  defect, not normal pagination behavior.
- Cursors are keysets: known local create/rename/move/delete mutations and sort-
  key-changing polls reset page one. Cross-tab mutations may move items across a
  cursor because this is an eventually consistent live view, not a snapshot;
  Refresh is always available.
- Do not add virtualization in this release. Verify smooth interaction and
  bounded entrance work with 240 accumulated items; animate only affected/new
  items and never issue React state updates per animation frame.

## Verification

Tests cover Skeleton/Empty/error actions, direction, reduced motion, stagger cap,
no poll replay, load success/error/retry/double-click/race, item/focus retention,
cursor clearing, and final-page removal of Load more.
Tests also cover local-mutation resets, cross-page deduplication, Refresh, and
the 240-item performance case.
