# Slice 2.22: Folder grid item

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2. Depends on 2.12 and 2.21.** Replaced FolderCardV2's
custom Card/action-bar shell with a shadcn Item-based grid representation.

## Work

- Add the official Item/ItemGroup source. Compose a vertical outlined Item with
  folder icon, full accessible name, truncated visible title, and direct folder/
  clip counts with correct singular/plural labels. Counts use slice 2.15's
  direct-visible-child rule, including failed clips and excluding uploading,
  cancelled, and deleted clips.
- One primary button opens the folder. The separate overflow slot must not create
  nested interactive elements or activate Open through event bubbling.
- Preserve normal/admin ownership behavior. Do not show size, upload date,
  recursive totals, selection checkbox, or drag handle.
- The containing explorer grid uses exactly one column below 640 px, two from
  640–1023 px, three from 1024–1279 px, and four at 1280 px and above inside
  `max-w-7xl`. Item shells in a row have equal height without stretching media.

## Verification

Tests cover primary pointer/Enter/Space activation once, overflow isolation,
focus ring, long/Unicode names, count grammar, admin context, no invalid nested
button markup, every count state, and responsive widths immediately below and
at every grid breakpoint.

## Implementation evidence

- The pinned shadcn Item/ItemGroup source is recorded in the registry. Folder
  cards now use a vertical outlined Item with a full-name primary button,
  truncated title, icon, and correctly pluralized direct counts.
- Actions occupy a sibling Item slot with event isolation and no nested
  interactive markup. Existing normal/admin capabilities and deletion flow are
  preserved through the typed item mapping.
- The grid locks `grid-cols-1`, `sm:grid-cols-2`, `lg:grid-cols-3`, and
  `xl:grid-cols-4` within `max-w-7xl`; focused interaction, Unicode, grammar,
  isolation, affordance, and breakpoint-contract tests pass.
