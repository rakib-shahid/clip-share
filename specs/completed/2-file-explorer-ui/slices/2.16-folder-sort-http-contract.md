# Slice 2.16: Folder sort HTTP contract

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2. Depends on 2.14 and 2.15.** Server sorting is exposed
through the existing folder endpoint.

## Work

- `GET /api/folders/{id}?sort=<enum>&cursor=<opaque>` defaults to latest.
- Return `400 invalid_sort` with field `sort` for an unknown value and
  `400 invalid_cursor` with field `cursor` for all cursor failures.
- Encode each `nextCursor` with the current folder/sort, phase, and last emitted
  keyset tuple. Never emit or accept an offset cursor.
- Add stable numeric `totalFolderCount`, `totalClipCount`, and `totalItemCount`
  response fields using slice 2.15's visible-direct-child definitions.
- Do not echo decoded cursor internals or SQL details. Authorization and generic
  not-found behavior run as before.
- Update the completed API contract by reference from this active slice; do not
  rewrite its historical text.

## Implementation evidence

- The endpoint strictly parses the seven-value enum, decodes a cursor bound to
  the requested folder and sort, and emits the versioned base64url keyset with
  no offset compatibility path.
- Contract tests cover every sort across two pages, omitted and percent-encoded
  sort input, mismatched/malformed cursors, stable totals, and error fields.
- The historical core API spec links here for this additive contract.

## Verification

HTTP tests cover every sort, omitted sort, encoded special input, mismatched
cursor/phase/tuple, normal/admin authorization, stable JSON fields and totals,
and page concatenation.
Existing clients without sort continue receiving folders A–Z and clips latest.
