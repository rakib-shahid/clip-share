# Slice 2.14: Folder sort and cursor types

## Status and outcome

**Completed September 12, 2026. Parent: main spec 2.** Pure backend sort parsing
and a versioned keyset cursor are available without changing SQL or routes.

## Work

- Define the closed enum `latest`, `oldest`, `name_asc`, `name_desc`,
  `size_desc`, `size_asc`, and `state`; empty input resolves to `latest`.
- Reject unknown/case-variant values as `invalid_sort` rather than guessing.
- Replace the offset-only cursor codec with base64url-encoded versioned keyset
  data that binds folder ID, sort enum, phase (`folders` or `clips`), the last
  emitted canonical sort tuple, and stable item ID. It contains no offset.
- Canonical tuples are normalized name+ID for folders; created time+ID for
  latest/oldest; normalized title+ID for name; known/null rank+size+created
  time+ID for size; and state rank+created time+ID for state.
- Decode only the documented schema/version; reject malformed, overflowed,
  wrong-folder, wrong-sort, invalid-phase, wrong-tuple-shape, or trailing data
  as `invalid_cursor`.

## Verification

Table tests cover every enum/default and phase, round trips, tie-heavy tuples,
tampering/mismatch classes, old offset-only cursors, numeric/time overflow,
padding variants, and fuzz/no-panic decoding. Cursor contents are identifiers
and ordering values only, never secrets.

## Implementation evidence

- `FolderSort` is a closed seven-value enum with strict parsing and a latest
  default; case variants and unknown values return `ErrInvalidSort`.
- The base64url/no-padding cursor binds version 1, folder, sort, phase, stable ID,
  and a strictly shaped sort key. Strict JSON, time/rank/size validation, and
  mismatch checks reject offsets, padding, trailing data, and malformed values.
- Table, mismatch, legacy/malformed, and fuzz tests pass without route or SQL
  changes.
