# Slice 2.34: Minimum pending transitions

## Status and outcome

**Completed September 13, 2026. Parent: main spec 2. Depends on slices 2.13,
2.27, and 2.28.** Fast explorer requests no longer reverse loading transitions
mid-animation or cause the content layout to jump.

## Work

- Define the application animation duration once in `web/src/lib/motion.ts` and
  derive Motion transition seconds and pending-state milliseconds from it. The
  accepted value is 150 milliseconds and can be tuned through that single
  constant.
- Hold successful folder navigation, refresh, and pagination pending states for
  at least that shared duration, enough for the accepted collection transitions
  to settle before reversing. Never add time after a naturally slower request.
- Keep abort and supersession semantics authoritative: delayed stale responses
  cannot commit or clear a newer request's pending state.
- Skip the artificial minimum for users requesting reduced motion.
- Present the retained-page refresh indicator as a fixed, non-layout-shifting
  status pill while the existing collection opacity treatment settles.

## Verification

- Unit tests cover remaining-duration calculation, elapsed requests, and the
  reduced-motion bypass. Existing request-race tests continue to pass.
- Lint, React tests/build, browser verification, and Docker runtime checks pass.
