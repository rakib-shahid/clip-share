# Slice 2.25: Compact list view

## Status and outcome

**Completed September 13, 2026. Parent: main spec 2. Depends on 2.17 and 2.21–2.24.** Renders the same
models/actions as a dense ItemGroup without duplicating domain logic.

## Work

- Desktop columns align media/name, state/type, size or direct counts, upload
  date, and overflow action. Column headings are visible or screen-reader
  available and remain associated with the collection.
- Both views are ordinary `ul`/`li` document collections, not ARIA grids or
  roving-tabindex composites. Tab reaches each primary action and overflow
  trigger in DOM order; arrow keys operate only inside an open menu.
- Below 640 px, collapse to icon/thumbnail, name, one secondary metadata line,
  and action trigger. Use CSS layout only; do not branch data or remount dialogs.
- Folders omit fabricated size/date. Clips use the same badges, progress, dates,
  preview eligibility, and menus as grid.
- View switching preserves folder, sort, loaded items, focus target where it
  still exists, and open dialogs; it writes only the explorer view preference.

## Verification

Tests compare grid/list accessible names/actions and item order, validate desktop
columns, exact 640 px collapse boundary, and 320 px layout; ensure no horizontal
page overflow; verify standard Tab order/no closed-list arrow navigation; and
prove view switches make no API request or media-state reset.
