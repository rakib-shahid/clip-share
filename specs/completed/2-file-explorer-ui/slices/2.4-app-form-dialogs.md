# Slice 2.4: Application form Dialog migrations

## Status and outcome

**Completed. Parent: main spec 2. Depends on 2.2.** Non-destructive form
surfaces in `App.tsx` and explorer naming now use the shared shadcn primitives
without changing mutation contracts.

## Work

- Migrate Change password, Create user, Create folder, Rename folder, and Rename
  clip to Dialog/Header/Description/Footer/Field/Label/Input composition.
- Enter submits once when valid and idle. Escape/outside closes only when idle.
- Trim outer whitespace at submission; preserve internal spaces, max lengths,
  password autocomplete attributes, API error placement, and CSRF requests.
- Focus the first useful field and return focus to the exact opener.

## Verification

Component tests cover submit, invalid/blank input, server error, double-submit
prevention, busy dismissal, Escape, outside click, and focus restoration for each
form family. No mutation contract or request body changes beyond trimming names.

## Implementation evidence

- Change password, Create user, Create folder, Rename folder, and Rename clip use
  `Dialog`, `Field`, `Label`, and `Input` composition.
- Dialogs guard duplicate submissions, disable dismissal while busy, preserve
  password whitespace, and trim only folder/user/clip names as specified.
- Close focus is restored to the exact element that opened a conditionally
  rendered dialog.
- `form-dialogs.test.tsx` covers all form families and the complete behavior
  contract; the full frontend suite passes 28 tests along with lint and build.
